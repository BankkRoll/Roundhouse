## Crypto evidence

`apps/api/src/lib/chacha20-poly1305.ts` and `apps/api/src/lib/age-file.ts`
stay hand-written. WebCrypto has no ChaCha20, and the code is small. The
tests below now pin it to the RFC, to the Go reference implementation and
to the full age conformance suite. Replacing it with `@noble/ciphers` would
add a dependency without closing any gap these tests leave.
- **RFC 8439** (`apps/api/test/fixtures/crypto/rfc8439.json`, checked by
  `apps/api/test/chacha20-poly1305.test.ts`). The vectors are extracted by
  script from the RFC text, not typed by hand. They cover:
  - ChaCha20 block: 2.3.2 and A.1 #1–#5.
  - ChaCha20 encryption: 2.4.2 and A.2 #1–#3.
  - Poly1305: 2.5.2 and A.3 #1–#11. #5–#11 are the reduction and carry
    edge cases, the ones a 13-bit-limb implementation is most likely to get
    wrong.
  - Poly1305 key generation: 2.6.2 and A.4 #1–#3.
  - AEAD: 2.8.2 (seal) and A.5 (open), compared byte for byte, tag
    included.

  All 28 pass.
- **golang.org/x/crypto differential** (`fixtures/crypto/x-crypto.json`):
  - 143 AEAD seals with plaintext of every length from 0 to 130 bytes plus
    the block edges up to 4097, varying AAD, and all-0xff keys and messages.
  - 291 Poly1305 tags over random, all-0xff, and r = 0xff… keys, for every
    message length from 0 to 96 bytes.

  All match, and every seal opens again.
- **C2SP CCTV age vectors** (`fixtures/age/cctv.json`, from
  `c2sp.org/CCTV/age`): all 68 non-armored vectors with an X25519 identity.
  - The success vectors decrypt to the expected SHA-256. They include 257-
    and 258-chunk files, a full final chunk, an empty payload, grease
    stanzas and multiple recipients.
  - Every failure vector is refused: header, HMAC, payload and no-match
    failures, including:
    - truncation at and inside chunk boundaries;
    - a missing or doubled final chunk;
    - an empty final chunk after a full one;
    - trailing garbage;
    - bad tags in any chunk;
    - low-order and identity shares;
    - non-canonical encodings.

  Before `71f51da`, 12 of these were wrongly accepted.
- **Reverse interop**: files written by `ageEncrypt` were decrypted with
  `filippo.io/age` v1.3.2 `age.Decrypt`. Sizes were 0, 1, 15, 16, 17,
  65535, 65536, 65537, 131072, 131073 and 300000 bytes, and all round-trip.
  The existing fixture covers the other direction: a file `filippo.io/age`
  wrote decrypts here.
- **Properties checked by reading the code**:
  - The tag is compared in constant time.
  - Nonces never repeat. The file key and STREAM nonce are fresh random
    bytes per file, the wrap key is derived from a fresh ephemeral key per
    file, and the STREAM nonce is an 11-byte big-endian counter plus the
    last-chunk flag.
  - The HKDF labels match age v1: `age-encryption.org/v1/X25519` salted
    with ephemeral share || recipient, `header`, and `payload` salted with
    the nonce.
  - The header MAC covers everything through `---`.
  - Chunks can't be reordered or truncated: the counter and last flag are
    in the nonce.

## Reviewed without findings

- Access control:
  - `resolveAccess` and the scope helpers.
  - Every scope helper takes the project from the stored row, so a path's
    workspace can't be paired with another workspace's project.
  - Environment IDs from requests are bound to their project through
    `environment_mismatch`.
  - The reauth guard is enforced by the router and the two-factor gate by
    middleware.
  - The newest routes: previews, environments, mesh and drain, registry
    storage, Cloudflare and Cloudflare for SaaS, shell, templates, and the
    project directory.
  - Token scopes, and MCP OAuth (exact redirect URI, PKCE S256,
    audience-bound tokens).
- GitHub:
  - Webhooks: the HMAC is checked over the raw body first, and replay is
    blocked by delivery ID and body hash.
  - Push routing is limited to the claiming workspace's installation.
  - Fork approval checks the label sender's collaborator permission with
    GitHub at approval time.
  - Fork builds get no build secrets, no registry credentials, a separate
    BuildKit daemon, and builder nodes reserved for them.
- Agent:
  - The envelope signature is checked over the exact payload bytes, with
    the node ID and expiry checked too.
  - Tar extraction refuses traversal, symlink parents and foreign hard
    links.
  - Secret file names can't contain path separators.
- Web:
  - CSP without `unsafe-inline` scripts, `frame-ancestors 'none'`,
    `nosniff`.
  - Same-origin checks on cookie mutations and cookie WebSocket upgrades.
  - Post-login redirects are sanitized, and external links go through
    `webUrl`.
  - No raw HTML sinks.
- SSRF:
  - `CLOUDFLARE_API_URL` is honored only with `ROUNDHOUSE_DEV=1`.
  - `GITHUB_API_URL` must be https, or http only in dev.
  - S3 and registry endpoints are instance-admin settings and must be
    origin-only https.
  - Git ref lookups and MCP client metadata don't follow redirects.
- Audit hash chain: verification recomputes every link and checks it
  against the Durable Object's checkpoints.
